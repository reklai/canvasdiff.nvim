1. INTRODUCTION                                       *canvasdiff-introduction*

CanvasDiff renders every changed file in your repository into ONE buffer -- the
canvas -- and lets you move through the whole review by file and by hunk
without opening a file at a time.

The canvas is modal. It is a `nofile` buffer that is not modifiable, so once
you are inside it you press single keys rather than typing `:`. That is why
the command surface below is small: every word in it earns its place by being
useful from OUTSIDE the canvas, or inside your own mapping.

Two things are worth knowing before you start:

- Worktree-backed lenses (`all`, `unstaged`, and a bare ref) have an editable
  new side. Press <CR> to jump into that file, edit it, then press CTRL-Space
  to return. The `staged` lens reads the index and commit ranges read commits,
  so those views are read-only and decline the jump.
- Reviews are independent. Two repositories open at once own separate
  canvases, separate sidebars, and separate sessions; closing one never
  disturbs the other.

==============================================================================
2. REQUIREMENTS                                       *canvasdiff-requirements*

- Neovim 0.12 or newer. This is the TESTED floor, asserted at plugin load
  and by |:checkhealth| (`:checkhealth canvasdiff`): the float, winbar and
  statuscolumn geometry CanvasDiff depends on is measured against 0.12, and
  those exact facts have differed across Neovim versions.
- `git` on your `PATH`.

Run `:checkhealth canvasdiff` after installing. Besides the probes above it
audits your `setup()` table for misspelled or removed options -- those merge
without complaint and silently do nothing.

Optional, each degrading to a plain canvas rather than an error:

- Tree-sitter parsers, for syntax highlighting inside the diff.
- An `lz4` shared library, for compacting very large canvases in memory. Its
  absence costs memory, never correctness.

==============================================================================
3. QUICK START                                          *canvasdiff-quickstart*

No setup call is required. With `git` on your path, inside a repository: >vim

    :CanvasDiff
<
That opens the `all` lens: every change between HEAD and your worktree. From
there:

    j / k           move a line, as usual
    ]h  [h          next / previous hunk
    ]f  [f          next / previous file
    CTRL-N  CTRL-P  scroll to the next / previous hunk (wraps)
    c               collapse or expand the file under the cursor
    <Tab>           next lens (what you are comparing)
    s               stage the hunk under the cursor
    u               unstage the hunk under the cursor
    S  /  U         stage / unstage this whole file
    <CR>            jump to this line in the real file
    CTRL-Space      (in the real file) come back to the canvas
    q               close the review

To change defaults, call `setup()` once: >lua

    require("canvasdiff").setup({
      context = 5,
      sidebar = { width = 40 },
    })
<

4. THE CANVAS                                               *canvasdiff-canvas*

The canvas buffer is named `canvasdiff://canvas/N`, where N identifies the
review. It is `buftype=nofile`, not modifiable, and carries no undo history,
which is why ordinary editing keys are free to be used as review commands.

Alongside it you may see:

sidebar~
    A tree of everything in the review, at two levels of content:
    directories and files, and under each unfolded file one row per HUNK --
    `@@ 88  render(state)  +3 −1`, the new-side line it starts at, the first
    line it writes, and its own counts. A hunk whose label came from a
    deleted line is struck through, as it is on the canvas. Selecting a row
    moves the canvas to that file or that hunk; `s` and `u` on it stage or
    unstage whichever the row names.

    The tree MIRRORS the canvas's folds, and mirrors nothing else. Fold a
    file and its hunk rows collapse into the single row the canvas shows,
    carrying the same summary as its placeholder --
    `▸ helpers.lua  (3 hunks, +9 −1)`. Fold a directory and it becomes one
    row summarising what it hides -- `▸ test/  (2 files, +9 −1)`. Automatic
    virtualization (see |canvasdiff-configuration|) is not a fold and never
    removes hunk rows: it collapses far-from-viewport sections for speed, and
    a tree that reflowed with it would move rows under your cursor on every
    scroll.

    `q` in the sidebar closes just the sidebar; `o` on the canvas, or
    |:CanvasDiff| `sidebar`, brings it back. Turn off the auto-open with
    `sidebar = { enabled = false }` -- the toggle still works.

status column~
    Each line's number in the file it belongs to, plus a one-cell green/red
    bar beside every added and deleted row, ghost deletions included.

pinned header~
    A one-row float directly under the winbar, showing the header of the
    file under the topline -- the same bar tint, counts and stage marks as
    the row it mirrors. It COVERS the first canvas row rather than pushing
    it down, so it never moves the view, and clicks fall through to the
    covered row. It hides itself while the real header row is at the top of
    the window (a copy over the original would double it) and on a folded
    placeholder, whose single row already is the header.

    Once the topline is inside a hunk the row continues with a breadcrumb --
    the file, then that hunk, then its ordinal in the file: >

        ▎ src/canvas.lua  (+12 −4) → @@ 88  render(state) · 3/5
<
    The hunk is named exactly as the sidebar's own row names it, so closing
    the sidebar loses nothing about where you are, and `3/5` says how much
    of the file is still ahead. On the rows before a file's first hunk there
    is no hunk to name and the crumb is absent. A narrow window keeps the
    ordinal: the label is cut to fit around it, and if even a label-less
    crumb will not fit, the crumb is dropped whole rather than drawn with
    its right edge past the window. Both separators are configurable
    (`crumb`, `crumb_sep`; see |canvasdiff-glyphs|).

scrollbar~
    A density map of where the changes are in the whole review, not just in
    the visible window. It scrolls, too: drag the thumb with the mouse to
    scrub the canvas live, or press anywhere else on the bar to jump to
    that spot. Clicks off the bar column keep their normal meaning --
    single-click places the cursor, double-click jumps into the file.
    Needs 'mouse' enabled (the default); without it the bar is
    display-only.

Each file's canvas header -- the tinted bar of an expanded file, or the `▸`
placeholder of a folded one -- carries the file's stage state after its
counts: `●` staged (green), `○` unstaged (yellow), both when a file was
staged and then changed again. These are the same markers the sidebar rows
show, so the canvas answers "is this staged?" with the sidebar closed. A
file that changed since you folded it away carries one more mark, always
last: a red, bold `●` (stale). It shows on the folded placeholder, on the
file's sidebar row, and on a folded directory's row, and it clears when you
unfold -- then you have seen it. A staged file that went stale reads `● ●`,
the same glyph told apart by colour and position. Committed ranges show no
stage state anywhere: they describe two commits, not your worktree.

Files are collapsible. Collapsing a file keeps it in the review and in the
sidebar; it just stops taking up canvas rows. This is the fastest way to work
through a large change: collapse each file as you finish with it.

5. LENSES                                                   *canvasdiff-lenses*

A lens is what the canvas is comparing. There are three named lenses:

    all         HEAD vs your worktree -- everything you have changed
    unstaged    the index vs your worktree -- what is not staged yet
    staged      HEAD vs the index -- what you have staged

Press <Tab> to move forward through them and <S-Tab> to move back, or name one
directly: >vim

    :CanvasDiff staged
<
A bare revision is also a lens: `:CanvasDiff main` shows your editable
worktree against `main`.

                                                        *canvasdiff-ranges*
Commit ranges compare committed content and are read-only:

    A..B        compare the two tips directly: A vs B
    A...B       compare merge-base(A, B) vs B

An omitted endpoint means HEAD: `main..` is `main..HEAD`, and `...topic` is
`HEAD...topic`. The top band shows the refs you asked for, marked
READ-ONLY. File jumps and staging are declined in a range lens.
Press <Tab> or <S-Tab> to leave a range: the canvas returns to the comparison
you were looking through when you entered it, or to HEAD vs WORKTREE when the
canvas opened straight into the range. `q` backs out the same way: on a
comparison stacked over a working view this session, the first press returns
to that view, and the next press closes the review and restores the buffer
from which its canvas was entered. A canvas opened straight into the range
has nothing to back out to, so one press closes. `:CanvasDiff close` always
closes in one step.

The winbar is one continuous band across the canvas and the sidebar
(`CanvasDiffWinbar`). The canvas half names the comparison, as in
`HEAD → WORKTREE`, and never varies with scroll -- the file and hunk you are
in are the pinned header's job (see |canvasdiff-canvas|). A committed range
renders `READ-ONLY  A → B` and tints the whole band edge to edge
(`CanvasDiffWinbarReadOnly`), sidebar half included, so the mode is visible
before the label is read.

The sidebar half reads `Files changed (N)  +A −D`. N counts changed files
rather than visible directory rows; the stats are the whole changeset's, and
are omitted when nothing is changed.

`--staged` and `--cached` are likewise refused by name rather than accepted as
synonyms, because `--staged` is one keystroke away from `unstaged` and the two
mean OPPOSITE things.

6. COMMANDS                                               *canvasdiff-commands*

                                                                *:CanvasDiff*
:CanvasDiff             Toggle the review: open it, or close it if it is
                        already open.

:CanvasDiff open        Open the review. Reopening an existing review
                        refreshes it in place.

:CanvasDiff close       Close the review, saving your position.

:CanvasDiff toggle      Same as `:CanvasDiff` with no argument.

:CanvasDiff refresh     Re-collect from Git and splice in what changed, so the
                        same TEXT stays under your cursor.

:CanvasDiff sidebar     Toggle the file-tree sidebar of the open review.
                        Works even when `sidebar.enabled` is false -- that
                        flag governs auto-open only. Warns when no review is
                        showing rather than opening one.

:CanvasDiff compare     Choose a base and comparison ref with two
                        `vim.ui.select` prompts. Does not checkout or fetch.

:CanvasDiff checkout    Choose and checkout a local branch.

:CanvasDiff all         Switch to the `all` lens.
:CanvasDiff unstaged    Switch to the `unstaged` lens.
:CanvasDiff staged      Switch to the `staged` lens.

:CanvasDiff {revision}  Compare your worktree against {revision}.
:CanvasDiff {A..B}      Compare the two commit tips, read-only.
:CanvasDiff {A...B}     Compare merge-base(A, B) against B, read-only.

Completion is available for every word above. At most one argument is
accepted; anything else reports what was wrong rather than guessing.

Words are matched before revision parsing, so a branch literally named
`close` or `sidebar` cannot hijack the subcommand; spell such a branch a way
only git reads, like `heads/sidebar`.

7. MAPPINGS                                               *canvasdiff-mappings*

Mappings are grouped by context. `global` is process-wide; the other contexts
name the buffer they apply to. Every one is configurable; see
|canvasdiff-configuration|.

Global~
    <leader>lb              Compare two local branches or revisions
    <leader>lc              Checkout a local branch

These are the two process-wide defaults. They are shown in the cheatsheet's
Global column. If another mapping already occupies either lhs, CanvasDiff
preserves that map and reports the collision.

The comparison picker lists local branches only. Its base prompt orders local
`main`, then `master`, then the remaining branches alphabetically; its second
prompt puts the checked-out local branch first. Full refs stay internal. It
never checks out, fetches, or writes refs.

On the canvas~
                                                        *canvasdiff-canvas-maps*
    <CR>, <2-LeftMouse>     Jump to this line in the real file
    za, c                   Collapse or expand this file
    ]f  /  [f               Next / previous file
    ]h  /  [h               Next / previous hunk
    CTRL-N  /  CTRL-P       Scroll to the next / previous hunk (wraps;
                            a folded file is one stop)
    <Tab>  /  <S-Tab>       Next / previous lens
    o                       Toggle the sidebar
    r                       Refresh the current diff
    s                       Stage this hunk -- or this file on its header
    u                       Unstage this hunk -- or this file on its header
    S                       Stage this file's changes (from anywhere in it)
    U                       Unstage this file (from anywhere in it)
    q                       Back out: leave a stacked comparison, else
                            close the review
    <leader>lh              Show keybind cheatsheet

Two canvas actions ship with no key at all:

    cycle_file_next         Scroll to the next file's diff (wraps)
    cycle_file_prev         Scroll to the previous file's diff (wraps)

                                                *canvasdiff-changed-behaviour*
Changed behaviour~

CTRL-N and CTRL-P now cycle by HUNK rather than by file. They used to scroll
one file's diff at a time; they now stop at every hunk, a folded file still
counting as exactly one stop -- the granularity the rest of the canvas
already worked at. Nothing else changed meaning: `S` and `U` are new keys,
not redefinitions of old ones.

The file-at-a-time behaviour is intact under the two names above, so putting
it back is one line: >lua

    require("canvasdiff").setup({
      keymaps = { canvas = {
        cycle_next = {}, cycle_prev = {},           -- free the keys
        cycle_file_next = "<C-n>",                  -- and take them
        cycle_file_prev = "<C-p>",
      } },
    })
<
Freeing them first is worth the extra line. Two actions claiming one key in
one context is not an error -- it is whichever mapping installs last, and
that is not a thing to depend on. Drop the first line and give the hunk cycle
other keys if you want both.

In the sidebar~

    <CR>, za, c, <2-LeftMouse>      Select this entry
    s                               Stage the row you are on -- this hunk,
                                    or this file
    u                               Unstage the row you are on
    q                               Close the sidebar (canvas stays open;
                                    `o` on the canvas reopens it)
    <leader>lh                      Show keybind cheatsheet

Single `<LeftMouse>` is deliberately NOT bound: it is how you position the
cursor, and stealing it would make the tree impossible to browse.

                                                        *canvasdiff-staging*
Each key is one explicit verb: `s` only ever stages and `u` only ever
unstages, without changing the worktree. The ROW decides scope, in both
windows: on a hunk's own canvas rows, or on a sidebar hunk row, the verb
takes that hunk; on a file header, a folded placeholder, a sidebar file row
-- anything that names no hunk -- it takes the whole file. `S` and `U` take
the whole file from anywhere inside it. A sidebar directory row declines.

Staging writes the index directly: the hunk's lines are spliced into the
staged blob, rather than a patch being generated and re-applied. A verb with
nothing to do reports it (`already staged`, `hunk already staged`, `nothing
staged`, `nothing staged here`) and performs no change. Staging is declined
when a modified loaded buffer refers to the file, so unsaved text is never
replaced by disk content, and hunk staging declines binary files and
renames toward the whole-file verb.

In the `unstaged` lens a staged hunk VANISHES, and that is the confirmation:
the lens shows what is not staged yet. One <Tab> on, in the `staged` lens,
it is there.

On a file that is BOTH staged and modified, hunk staging needs a lens whose
b side is the one the verb writes: `u` works only in the staged lens, and
`s` declines only in the staged lens. In the wrong lens the hunk you see is
measured against a text the index does not hold, and rather than guess which
hunk you meant the verb declines and names a lens to use. `S` and `U` still
work from anywhere.

In a file you jumped to~
                                                          *canvasdiff-jump-back*
    CTRL-Space              Return to the canvas

This one mapping is set on the real file's buffer only for the duration of the
jump, and removed afterwards. Everything else in that buffer -- macros,
operators, your own mappings -- keeps working, because it is a buffer you are
actually editing.

There is deliberately no second key for it. If your terminal does not transmit
CTRL-Space, the jump loop has no exit, and a loud failure is better than a
subtly half-working one. To bind your own: >lua

    require("canvasdiff").setup({
      keymaps = { file = { back = "<C-g>" } },
    })
<

8. CONFIGURATION                                     *canvasdiff-configuration*

Call `setup()` with any subset of the table below. Anything you omit keeps its
default. >lua

    require("canvasdiff").setup({
      context = 3,
      base = "HEAD",

      keymaps = {
        global = {
          compare = "<leader>lb",
          checkout = "<leader>lc",
        },
        canvas = {
          jump       = { "<CR>", "<2-LeftMouse>" },
          collapse   = { "za", "c" },
          next_file  = "]f",
          prev_file  = "[f",
          next_hunk  = "]h",
          prev_hunk  = "[h",
          cycle_next = "<C-n>",
          cycle_prev = "<C-p>",
          -- The file axis CTRL-N/P used to walk. `{}` is "disabled", so no
          -- map exists until you ask for one; see
          -- |canvasdiff-changed-behaviour|.
          cycle_file_next = {},
          cycle_file_prev = {},
          lens_next  = "<Tab>",
          lens_prev  = "<S-Tab>",
          sidebar    = "o",
          refresh    = "r",
          stage      = "s",
          unstage    = "u",
          stage_file   = "S",
          unstage_file = "U",
          close      = "q",
          help       = "<leader>lh",
        },
        sidebar = {
          select = { "<CR>", "za", "c", "<2-LeftMouse>" },
          stage   = "s",
          unstage = "u",
          close  = "q",
          help   = "<leader>lh",
        },
        file = {
          back = "<C-Space>",
        },
      },

      sidebar      = { enabled = true, width = 32 },
      scrollbar    = { enabled = true },
      statuscolumn = { enabled = true },
      session      = { enabled = true },
      paged        = { enabled = true, min_rows = 20000 },
      highlight    = { enabled = true, margin = 100, debounce_ms = 30 },
      watch        = { enabled = true, debounce_ms = 200 },
      virt         = {
        enabled      = true,
        max_files    = 200,
        max_lines    = 100000,
        margin       = 100,
        max_expanded = 20,
      },
    })
<
Every mapping accepts a string or list. `false`, `""`, or `{}` disables it.
For the global compare and checkout mappings, repeated `setup()` calls
remove/rebind only maps CanvasDiff still owns by exact callback and metadata
identity. A foreign collision or later takeover is never overwritten or
deleted. A canonical compare/checkout collision is rejected before any global
mapping mutation.

                                                           *canvasdiff-paged*
Large reviews~

Above `paged.min_rows` canvas rows, CanvasDiff renders the review from a
page-backed store instead of writing every line into the buffer. The buffer
then holds one blank line per row and the text is drawn as you scroll, which
is what makes a review of a million rows open and scroll at all.

You will notice three differences on such a review:

- Syntax highlighting inside hunks is absent. The elevation, the margin
  hues, file bars and deleted-line ghosts all remain.
- Other plugins that read the buffer's lines see blank lines, because that is
  genuinely what is in the buffer.
- `/` and `y` need CanvasDiff's own search and yank, which read the store.
- The cursor stays in column 0 and a visual yank copies empty lines, for the
  same reason. Row addressing is exact -- folds, motions, marks and search
  positions are all unaffected -- but column addressing is not.

Set `paged = { enabled = false }` to always use the ordinary canvas, at the
cost of memory on very large reviews. Below the threshold nothing changes.

                                                  *canvasdiff-highlight-diff*
Diff row colouring~

There is one rendering, made of three channels, every value derived from the
live colourscheme when the canvas draws:

- Elevation says CHANGED: an added row's background -- and a wholly deleted
  file's rows -- is `Normal`'s background moved 4% toward the luminance pole
  (white on a dark scheme, black on a light one). Hueless on purpose: on a
  canvas most of the screen is changed rows, so a hued wash would spend the
  strongest visual channel on the least interesting fact.
- Dimming says REMOVED: ghost deletion lines -- and a wholly deleted file's
  rows, the only real `-` rows left -- use `Normal`'s foreground moved 30%
  toward its background, a factor measured so a deletion never reads dimmer
  than a comment. Ghosts are additionally struck through: parked at comment
  brightness by that very floor, the strikethrough is what separates a
  deleted block from a comment block at a glance.
- The margin hue says WHICH DIRECTION: green/red only on the one-cell
  `+`/`-` prefix and the statuscolumn bar (the `gutter` glyph, default `▎`),
  from `DiffAdd`/`DiffDelete`'s foreground, or a fixed green/red pair when
  those groups are background-only. The bar needs
  `statuscolumn.enabled = true` (the default); the prefix is in the text and
  always there.

The groups, all defined with `default = true` so a colourscheme or an
explicit `nvim_set_hl()` of your own always wins over the derived defaults:

    CanvasDiffAdd            derived neutral elevation; an added row's
                             background
    CanvasDiffDel            elevation plus dimmed foreground; a wholly
                             deleted file's real rows
    CanvasDiffGhost          dimmed, struck-through foreground, no
                             background; ghost deletion lines
    CanvasDiffPrefixAdd      derived green/red foreground; the `+`/`-`
    CanvasDiffPrefixDel      prefix cell
    CanvasDiffGutterAdd      the same green/red; the statuscolumn bar
    CanvasDiffGutterDel
    CanvasDiffWordAdd        bold + underline; the changed span within a
    CanvasDiffWordDel        line
    CanvasDiffFileBar        derived bar elevation; the file header row and
                             its pinned copy
    CanvasDiffWinbar         WinBar link; the top band
    CanvasDiffWinbarReadOnly Visual link; the band's read-only tint
    CanvasDiffSidebarHunk    Comment link; a sidebar hunk row, whole
    CanvasDiffHunkDel        CanvasDiffGhost link; a hunk label taken from a
                             deleted line -- struck, in the sidebar row and
                             in the pinned header's crumb alike

The old `highlight.diff` option (`"quiet"`/`"classic"`/`"gutter"`) no longer
exists -- there is nothing to pick between. A leftover `highlight.diff = ...`
in a config gets one diagnostic from `setup()` and is otherwise ignored;
override the groups above instead.

                                                          *canvasdiff-glyphs*
Glyphs~

The markers CanvasDiff draws default to Unicode. For a terminal or font that
cannot render them: >lua

    require("canvasdiff").setup({ glyphs = "ascii" })
<
Or override individual slots with a table. An unknown slot name is REPORTED
rather than ignored, because a silently-dropped option looks exactly like the
plugin failing to honour it.

Two slots are separators rather than single-cell markers, and both belong to
the pinned header's breadcrumb (see |canvasdiff-canvas|): `crumb`, between the
file and the hunk, and `crumb_sep`, between the hunk and its ordinal. Their
surrounding spaces are part of the configured value, because the file part of
that row is a byte-for-byte mirror of the header row it covers -- the
separator owns every character between the two fields. >lua

    glyphs = { crumb = " → ", crumb_sep = " · " }   -- default
    glyphs = { crumb = " -> ", crumb_sep = " | " }  -- what "ascii" selects
<

                                                          *canvasdiff-legacy*
Options that no longer exist are reported the same way. In particular, keymaps
used to be one flat table; passing that shape now warns and tells you the
grouped shape to use, instead of silently falling back to every default.

==============================================================================
9. SESSIONS                                               *canvasdiff-sessions*

Closing a review records where you were: the lens, the file, the line, and
which files you had collapsed. Reopening restores it.

State is written under |stdpath()| `"state"`, one record per repository, so two
repositories never share a position. Disable it with
`session = { enabled = false }`. A saved comparison whose branch no longer
exists falls back to the default lens on open, with a message saying so.

The lens is also remembered in memory, per repository, for the current Neovim
session -- close in `staged`, reopen in `staged`, even with sessions disabled.
Opening resolves the comparison most-specific first: an explicit lens from the
caller, then an explicit base, then the in-memory last lens, then the session
file, then the configured default. A remembered comparison whose ref has since
died degrades to the default lens with the same message as a saved one.

Because close-then-open restores your position, it is also the repair for a
canvas that has somehow diverged from what Git reports -- press `q`, then
`:CanvasDiff`. That is why there is no separate hard-rebuild key.

10. LUA API                                                    *canvasdiff-api*

Every function below is on the `canvasdiff` module: >lua

    local canvasdiff = require("canvasdiff")
<
canvasdiff.setup({opts})                                *canvasdiff.setup()*
        Merge {opts} into the configuration. Optional; defaults apply if it is
        never called.

canvasdiff.open({opts})                                  *canvasdiff.open()*
        Open a review in the current window's repository.

canvasdiff.close()                                      *canvasdiff.close()*
        Close the review that owns the current window, saving its position.

canvasdiff.toggle()                                    *canvasdiff.toggle()*
        Open, or close if already open.

canvasdiff.sidebar()                                  *canvasdiff.sidebar()*
        Toggle the file-tree sidebar of the showing review. Independent of
        `sidebar.enabled`, which governs auto-open only. Warns when no
        review is showing.

canvasdiff.refresh()                                  *canvasdiff.refresh()*
        Re-collect from Git and splice in what changed.

canvasdiff.compare()                                  *canvasdiff.compare()*
        Pick two branches/revisions and open their read-only comparison.

canvasdiff.checkout()                                *canvasdiff.checkout()*
        Pick a local branch and switch to it. Refused while any repository
        buffer has unsaved changes; offers no force, stash, or detached-HEAD
        operations.

canvasdiff.track()                                      *canvasdiff.track()*
        Pick a remote-tracking ref, then create and switch to a local branch
        tracking it. Never fetches.

canvasdiff.set_lens({lens})                          *canvasdiff.set_lens()*
        Set the lens to `"all"`, `"unstaged"` or `"staged"`.

canvasdiff.cycle_lens({delta})                     *canvasdiff.cycle_lens()*
        Move {delta} steps through the named lenses. Wraps.

canvasdiff.set_branch({ref})                        *canvasdiff.set_branch()*
        Compare the worktree against {ref}.

canvasdiff.set_range({range})                        *canvasdiff.set_range()*
        Compare an `A..B` or `A...B` committed range.

canvasdiff.stage()                                    *canvasdiff.stage()*
canvasdiff.unstage()                                *canvasdiff.unstage()*
        Stage or unstage the whole FILE selected in the canvas/sidebar --
        what `S` and `U` do, whatever row the cursor is on. Hunk staging is
        a keypress rather than an API call: it resolves the row under the
        cursor, which a function called from anywhere has not got. A verb
        with nothing to do notifies and returns false without touching Git.

canvasdiff.set_base({base})                           *canvasdiff.set_base()*
canvasdiff.toggle_base()                           *canvasdiff.toggle_base()*
        Set or toggle the base revision.

11. TROUBLESHOOTING                                *canvasdiff-troubleshooting*

Nothing opens~
    You are probably not inside a Git worktree. CanvasDiff reports this rather
    than opening an empty canvas.

CTRL-Space does nothing~
    Your terminal is not transmitting it. Bind another key; see
    |canvasdiff-jump-back|.

Shifted or modified keys do nothing~
    Classic terminal encoding cannot carry a modifier on every key. This is
    why the defaults avoid Shift-Space, which arrives as a bare Space almost
    everywhere. <S-Tab> and CTRL-Space are not affected.

A configured mapping never appears~
    Check for the flat pre-1.0 keymaps shape, which warns on `setup()`, and
    for a misspelled key -- `canvas.colapse` is accepted by the merge and then
    never found. For `global.compare` or `global.checkout`, also check
    CanvasDiff's warning: a pre-existing global map is deliberately preserved.

Syntax highlighting is missing inside the diff~
    No Tree-sitter parser is installed for that filetype. The canvas still
    renders; only the syntax tier is absent.

Large reviews feel slow~
    Collapse files you have finished with. If a single file is enormous,
    `virt.max_lines` and `virt.max_files` bound how much is decorated.

Syntax highlighting vanished on one big review~
    That review crossed `paged.min_rows` and is page-backed. See
    |canvasdiff-paged|.
